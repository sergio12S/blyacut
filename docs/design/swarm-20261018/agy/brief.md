# Технический дизайн-бриф: Agent Experience & Creative Workflows (BlyaCut)

**Роль:** Архитектор агентского взаимодействия и креативных рабочих процессов (Agent Experience / Creative Workflows Architect)  
**Проект:** BlyaCut (десктопный видеоредактор на Tauri 2, Rust, Vue 3, FFmpeg, MCP)  
**Рабочая область:** `docs/design/swarm-20261018/agy/`  
**Дата:** 18 октября 2026  
**Версия:** 1.1.0 (с чётким разделением `[РЕАЛИЗОВАНО В 0.2]` и `[ПРЕДЛОЖЕНИЕ ДЛЯ SWARM / PROPOSED]`)  

---

## 1. Концепция и цели

BlyaCut соединяет детерминированное локальное ядро редактирования на Rust с внешними агентскими системами (GBRAIN/MCP) без навязывания облачных подписок, утечки данных и риска повреждения пользовательского проекта.

Данный документ описывает интерфейс управления агентами (Agent Control Surface), разграничение полномочий, систему расширяемых эффектов и обработку параллельной работы, строго разделяя **текущую реализацию BlyaCut 0.2** и **архитектурные предложения (PROPOSED)**.

---

## 2. Реализация ядра 0.2 vs Архитектурные предложения (PROPOSED)

Чтобы исключить расхождения между спецификацией и кодовой базой, ниже приведена матрица текущих возможностей и предлагаемых улучшений:

| Подсистема | Текущая реализация (BlyaCut 0.2) `[РЕАЛИЗОВАНО]` | Предложение для Swarm `[PROPOSED]` |
|---|---|---|
| **История и Undo** | Хранение до 100 полных снимков проекта (`Vec<Project>`). Undo/Redo полностью заменяет снимок проекта и инкрементирует ревизию. | Вычисление гранулярных обратных операций (`inverse_edits`) для селективной отмены только агентских правок без отката ручных действий человека. |
| **Ошибки протокола** | Ошибки возвращаются как простые строки (например, `"Mismatched revision: expected 14, actual 15"`, `"Path outside authorized folder"`). | Структурированные JSON-ответы формата `{"error": "STALE_REVISION", "expected": 14, "current": 15, "conflict_summary": "..."}`. |
| **Обнаружение возможностей** | Стандартный вызов MCP `tools/list` протоколов `2025-11-25` и `2025-06-18`. | Выделенный эндпоинт `capabilities_list` с динамическими флагами и лимитами. |
| **Управление экспортом** | `export_video` вызывается напрямую через MCP без обязательного диалога подтверждения в GUI (проверяется только путь внутри `allowed_root`, уникальность файла и ревизия). | Модальный диалог в GUI с подтверждением параметров рендера человеком перед запуском FFmpeg. |
| **Символические ссылки** | Разрешены (`std::fs::canonicalize`): если канонический целевой файл лежит внутри `allowed_root`, импорт разрешён. | Расширенные политики песочницы для симлинков на сетевые диски. |
| **Рецепты эффектов (v1)** | Только формат JSON. Строго 7 типов шагов: `brightness`, `contrast`, `saturation`, `hue`, `low_pass`, `high_pass`, `echo`. В схеме проекта v3 хранятся полные копии рецептов. | Поддержка произвольных фильтрграфов FFmpeg, YAML-манифестов и сторонних DSP. |
| **Блокировки треков** | Отсутствуют. Защита от коллизий обеспечивается только проверкой `expected_revision`. | Декларативная аренда дорожек `claim_track_intent` с тайм-аутом для предупреждения конфликтов в рое. |
| **Провенанс артефактов** | Стандартный контейнер MP4. Провенанс в виде цифровых подписей агента отсутствует. | Встраивание JSON-метаданных с цифровой подписью агента и хэшем рецепта в MP4 atom. |

## 3. Архитектура агентского интерфейса управления (Agent Control Surface)

### 3.1. Единый источник правды и транзакции `[РЕАЛИЗОВАНО В 0.2]`
Редакторское ядро Rust (`crates/core`, `crates/session`) является единственным владельцем состояния проекта:
- Любая мутация таймлайна (ручной клик или вызов через MCP) выполняется через `Editor::batch`.
- Каждая успешная операция инкрементирует целочисленную монотонную ревизию (`revision`).
- Батч сначала проверяется на изолированном проекте-кандидате (`Candidate Project`). При любой ошибке валидации состояние и история проекта остаются полностью нетронутыми.
- Несовпадение ревизии отвергает операцию со строковой ошибкой `Mismatched revision`.

### 3.2. Предлагаемая модель обратимых батчей (Reversible Batches) `[PROPOSED]`
В будущих версиях предлагается расширить `Editor::batch` автоматической генерацией инверсного списка команд (`inverse_edits`). Это позволит реализовать выборочный откат (Selective Rollback): пользователь сможет отменить конкретное действие агента (например, автодакинг аудио), сохранив последующие ручные разрезы видео. В 0.2 отмена выполняется полным снимком состояния.

### 3.3. Разграничение прав доступа (Permission Tiers)
1. **Tier 0: Inspect `[РЕАЛИЗОВАНО]`**:
   - Инструменты: `get_project`, `get_timeline`, `get_session`, `list_effect_recipes`.
   - Не требуют подтверждения, не меняют состояние.
2. **Tier 1: Safe Batch `[РЕАЛИЗОВАНО]`**:
   - Инструменты: `apply_edits`.
   - Ограничения: до 20 операций, строго без `delete_clip`.
   - При совпадении `expected_revision` применяется автоматически.
3. **Tier 2: Proposal Diff Review `[РЕАЛИЗОВАНО]`**:
   - Инструменты: `propose_edits`.
   - Триггеры: наличие хотя бы одной операции `delete_clip` или пакет более 20 правок.
   - Требует обязательного подтверждения человеком в настольном приложении (кнопки Apply/Reject в сайдбаре).
4. **Tier 3: Export & Render `[РЕАЛИЗОВАНО]`**:
   - Инструменты: `export_video`, `cancel_export`.
   - Поведение в 0.2: если целевой путь абсолютный, заканчивается на `.mp4`, не существует на диске, а родительская папка лежит внутри `allowed_root`, экспорт запускается в фоне напрямую через MCP.
   - `[PROPOSED]`: Предложение добавить опциональный модальный запрос подтверждения параметров рендера в GUI перед стартом экспорта.

### 3.4. Периметр файловой системы `[РЕАЛИЗОВАНО В 0.2]`
- Доступ строго ограничен папкой `allowed_root`, выбранной пользователем.
- Пути канонизируются с помощью `std::fs::canonicalize`. **Символические ссылки РАЗРЕШЕНЫ**, если их реальный целевой путь после резолва остаётся внутри `allowed_root`.
- Исходные медиафайлы защищены от удаления и перезаписи агентом.
- Экспорт разрешён только в новый `.mp4` файл (защита от перезаписи существующих роликов).

## 4. Конкурентность, коллизии и устаревшие ревизии

### 4.1. Текущий механизм защиты в 0.2 `[РЕАЛИЗОВАНО]`
- Каждый запрос мутации (`apply_edits`, `propose_edits`, `undo`, `redo`, `export_video`) обязан содержать поле `expected_revision`.
- Если за время подготовки плана пользователь или другой агент изменил ревизию проекта, сессия возвращает строковую ошибку (например, `Mismatched revision: expected 14, actual 15`).
- Агент обязан повторно вызвать `get_timeline` / `get_project`, адаптировать временные метки и повторить вызов с новой ревизией.

### 4.2. Предлагаемые улучшения для роя (Swarm Protocol) `[PROPOSED]`
1. **Структурированный пакет коллизии**: вместо простой текстовой строки возвращать машиночитаемый JSON-объект с деталями расхождения.
2. **Аренда намерений дорожек (`claim_track_intent`)**:
   - Агент регистрирует временную аренду (например, на 15 секунд на дорожку `audio-2`).
   - Другие агенты видят статус занятости дорожки через `get_session` и не генерируют конкурирующие батчи.

## 5. Система эффектов без переустановки (Zero-Recompile Effect System)

Пользователю требуется возможность создавать и настраивать аудио- и видео-эффекты без пересборки и переустановки десктопного редактора.

### 5.1. Рецепты эффектов Recipe v1 `[РЕАЛИЗОВАНО В 0.2]`
В кодовой базе (`crates/core/src/effects.rs`) реализована строгая, безопасная спецификация Recipe v1:
- **Формат**: Только JSON (YAML не поддерживается и отклоняется валидатором).
- **Хранение**: В схеме проекта v3 копии рецептов хранятся прямо в структуре проекта. На диске рецепты загружаются и сохраняются в папке `effects/` внутри `allowed_root` через инструменты `list_effect_recipes` и `create_effect_recipe`.
- **Строгий белый список шагов (от 1 до 16 шагов)**:
  1. `brightness` (`gain_milli`: 0..=2000)
  2. `contrast` (`gain_milli`: 0..=3000)
  3. `saturation` (`gain_milli`: 0..=3000)
  4. `hue` (`degrees`: -360..=360)
  5. `low_pass` (`frequency_hz`: 20..=20000)
  6. `high_pass` (`frequency_hz`: 20..=20000)
  7. `echo` (`delay_ms`: 1..=2000, `decay_milli`: 0..=900)
- **Безопасность**: Запрещены любые произвольные строки фильтров FFmpeg, шелл-команды или нативный код (`#[serde(deny_unknown_fields)]`). Любой неизвестный параметр приводит к ошибке валидации.

### 5.2. Будущие этапы расширения плагинов `[PROPOSED]`
- **Этап 2 (WASM DSP & WGSL Shaders)**: Изолированная среда исполнения Wasmtime для сложной обработки звука (компрессоры, ревербераторы) и шейдеры WGSL для аппаратного предпросмотра в WebGPU с жестким лимитом памяти (64MB) и запретом системных вызовов.
- **Этап 3 (Sidecar Services)**: Внешние локальные процессы через Unix Domain Sockets для транскрибации (whisper.cpp) и разделения аудиодорожек.

## 6. Пользовательский сценарий в прототипе (Prototype Walkthrough)

Интерактивный прототип (`docs/design/swarm-20261018/agy/prototype.html`) наглядно демонстрирует рабочий процесс, снабжая каждый элемент пометками о текущем статусе:

1. **Creative Brief**: Человек формулирует творческую задачу на русском языке.
2. **План и Diff Preview**:
   - План содержит операцию удаления `delete_clip`, активируя режим **Tier 2 Proposal `[РЕАЛИЗОВАНО]`**.
   - На таймлайне отображается предлагаемый визуальный дифф `[PROPOSED UI]`: красным пунктиром подсвечены удаляемые участки, зеленым — новый аудиоклип.
3. **Human Refine `[PROPOSED UI]`**:
   - Человек корректирует параметры эффектов (насыщенность, срез частот) в карточке до утверждения батча.
4. **Фиксация и ревизия `[РЕАЛИЗОВАНО]`**:
   - Нажатие «Review & Commit Batch» применяет батч с проверкой ревизии (`#14 -> #15`).
   - Кнопка Undo восстанавливает состояние таймлайна из снимка истории проекта.
5. **Симуляция коллизии `[PROPOSED]`**:
   - Кнопка «Test Collision» симулирует вклинивание параллельного агента и демонстрирует реакцию на устаревшую ревизию.
6. **Фоновый рендер и очистка `[РЕАЛИЗОВАНО]`**:
   - Запуск фонового рендера, отображение прогресса и кнопка отмены (`cancel_export`), гарантирующая удаление временных файлов в scratch-директории.
   - Карточка провенанса с демонстрацией метаданных артефакта `[PROPOSED]`.
