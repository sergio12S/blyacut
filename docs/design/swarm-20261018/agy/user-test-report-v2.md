## 2. Количество вызовов и итераций

Работа выполнена за **2 автономные итерации** (два независимых сессионных запуска скрипта через `scripts/mcp-script.py`), суммарно **30 вызовов инструментов MCP**:

### Итерация 1 (`iteration1.py`) — 24 вызова:
1. `get_session` → `{"access": {"allowed_root": "~/Movies/BlyaCut-agy-demo-v2", "mode": "autonomous"}, "pending_proposal": null, "render_job": null}`
2. `list_effect_recipes` → загружено 36 встроенных рецептов (`builtin-*`)
3. `create_effect_recipe` → создан кастомный рецепт:
```json
{
  "path": "~/Movies/BlyaCut-agy-demo-v2/effects/blyacut-cyber-glow.json",
  "recipe": {
    "id": "blyacut-cyber-glow",
    "name": "Cyber Glow",
    "steps": [
      {"effect": "saturation", "gain_milli": 1600},
      {"effect": "chromatic_aberration", "pixels": 6},
      {"effect": "vignette", "strength_milli": 400},
      {"amount_milli": 250, "effect": "sharpen"}
    ],
    "version": 1
  }
}
```
4–8. `create_title_card` (5 вызовов) → созданы и автоматически импортированы `title1.mp4`..`title5.mp4` с asset ID:
- `a40c8d4b-b3bb-404f-9efc-5f1ce88e539c`
- `feb1210a-7c81-4f23-bf73-8db1fb9007cb`
- `dfd80d19-8953-4560-b703-db993d6a9e8c`
- `d19a8774-fb96-43be-a515-316be20439cc`
- `8adecc45-da84-4e1c-8ef2-a5a72c909654`
9–15. `import_media` (7 вызовов) → импортированы 6 видеоклипов и 1 аудиофайл.
16. `get_project` → чтение актуальных ID дорожек (`vt=4ae2e0e5-393c-454f-b2a6-3fd543c676f0`, `at=8769a785-88dc-4297-bb6a-966f0a22ab6c`, ревизия 12).
17. `apply_edits` (Batch 1: 15 операций добавления клипов и чернового аудио).
18. `apply_edits` (Batch 2: 14 операций тримминга аудио, настройки громкости и назначения эффектов на все клипы).
19. `get_timeline` → проверка длительности и чистоты таймлайна (`duration_ms = 39000, warnings = []`).
20–25. `preview_frame` (6 вызовов) → рендер кадров превью в точках 1500мс, 5000мс, 8500мс, 15000мс, 23000мс, 37500мс.
26. `save_project` → сохранён проект `promo-v2.blyacut` (ревизия 14).
27. `export_video` → запущен экспорт `blyacut-promo-v2.mp4` (ревизия 14).
28. Поллинг `get_session` до завершения рендера.

### Итерация 2 (`iteration2.py`) — 6 вызовов:
1. `open_project` → загружен `promo-v2.blyacut` (ревизия 1).
2. `get_timeline` → `duration_ms = 39000, warnings = []`.
3. `apply_edits` → снижение `gain_milli` до 650 на `c-audio-bed` для устранения перегрузки лимитера.
4. `save_project` → сохранён чистовой проект `promo-v2b.blyacut` (ревизия 2).
5. `export_video` → запущен чистовой экспорт `blyacut-promo-v2b.mp4`.
6. Поллинг `get_session` до завершения рендера.

## 3. Какие warnings были получены и как исправлены

### Предупреждение 1: Несовпадение длины звука и видео
При сборке Batch 1 на аудиодорожку был положен исходный файл `music_synthwave.wav` длиной 40.00 с при длительности видеоряда 39.00 с.  
Ответ инструмента `apply_edits`:
```json
{
  "warnings": [
    "Audio runs 1.00 s past the last video clip (39.00 s–40.00 s): black frames; trim/fade the audio or add video"
  ]
}
```
**Исправление**: В Batch 2 применён `trim_clip` для `c-audio-bed` на интервал `start_ms: 0, end_ms: 39000`.  
Результат следующего `apply_edits`:
```json
{
  "warnings": []
}
```
И подтверждение из `get_timeline`:
```json
{
  "duration_ms": 39000,
  "warnings": []
}
```

### Предупреждение 2: Перегрузка лимитера по громкости звука
В первом экспорте (`blyacut-promo-v2.mp4`) аудио было отрендерено с `gain_milli: 1000`.  
После завершения экспорта опрос `get_session` вернул дословно:
```json
{
  "error": null,
  "id": "d49be0ef-b71a-4aea-96f3-6330076bd712",
  "loudness": {
    "mean_db": -12.9,
    "peak_db": 0.0
  },
  "output": "~/Movies/BlyaCut-agy-demo-v2/blyacut-promo-v2.mp4",
  "progress": 1.0,
  "revision": 14,
  "status": "complete",
  "warnings": [
    "Audio peaks at 0.0 dBFS and hits the limiter; lower gain_milli on loud clips"
  ]
}
```
**Исправление**: В Итерации 2 проект был открыт через `open_project`, и через `apply_edits` уровень усиления был скорректирован на `gain_milli: 650` (линейное ослабление ~ -3.7 dB). Экспортирован файл `blyacut-promo-v2b.mp4`.

## 6. Что было удобно, а что неудобно

### Удобно:
1. **Режим `--autonomous`**: Устраняет главную боль v1 — агенту не нужно ждать человека у экрана; пакеты до 100 правок и удаление клипов применяются мгновенно.
2. **Инструмент `create_title_card`**: Создаёт полноценное видео с кастомным цветом текста, фона и системными шрифтами (поддерживает переводы строк `\n` и кириллицу) и сразу возвращает `asset_id`.
3. **Инструмент `preview_frame`**: Позволяет агенту «видеть» результат монтажа в конкретный момент времени без дорогостоящего экспорта всего файла.
4. **Контур `warnings`**: Сразу предупреждает о несинхронном окончании аудио и видео, исключая экспорт роликов с чёрными хвостами.
5. **Анализ `loudness`**: Автоматический замер `peak_db` и `mean_db` прямо в объекте `render_job` с готовыми рекомендациями по коррекции гейна.
6. **Персистентность `save_project` / `open_project`**: Удобно разбивать сложную работу на итерации (монтаж → рендер → анализ → доводка).

### Неудобно:
1. **Инкремент ревизии при `create_title_card`**: Так как инструмент по умолчанию импортирует титр в проект, он увеличивает `revision`. Агент должен брать актуальную ревизию из ответа `create_title_card` либо повторно запрашивать `get_project`.
2. **Сброс ревизии в `open_project`**: При открытии сохранённого файла ревизия инициализируется заново (становится `1`), поэтому скрипт обязан использовать ревизию из возвращаемого объекта `open_project`.

## 8. Итоговая оценка и Топ-3 улучшения

### Итоговая оценка: 9.8 / 10
BlyaCut в режиме Headless Autonomous Studio превратился в полноценную автономную студию видеомонтажа, готовую к промышленной автоматизации без человека.

### Топ-3 предложения по развитию:
1. **Титры поверх существующего видео (Overlay Title)**: Добавить в `create_title_card` или как эффект возможность накладывать текст поверх уже идущего видеоклипа (альфа-канал/плашка), чтобы титры могли быть не только отдельными перебивками, но и плавающими подписями.
2. **Пакетный превью нескольких кадров (`preview_frames`)**: Добавить возможность передать массив таймкодов `[1500, 5000, 8500, ...]`, чтобы FFmpeg сгенерировал серию PNG за один проход фильтра, экономя время на запуск процессов.
3. **Инструмент предварительного замера аудио (`probe_audio_loudness`)**: Позволить агенту замерить пик и среднюю громкость импортированного трека до экспорта проекта, чтобы сразу выставить оптимальный `gain_milli`.
